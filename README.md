# AI-cross-agent · 跨终端 AI 协作套件

让 **Claude Code、Codex** 等多个 AI 编程终端，围绕同一个项目**接力协作**：
任何一个终端开工前自动读到「别人上次干了什么」，收工时自动留下「这次干了什么」。
你不再需要在不同工具之间手动复述上下文。

> 一句话：给多个 AI 终端装上一块**共享记忆**。

---

## 解决什么问题

不同 AI 终端的对话彼此隔离。你用 Claude Code 改了一半，切到 Codex 继续，Codex 却对前因
一无所知，只能从头解释。本套件用磁盘上一份**共享的会话摘要**打通它们：

```
        ┌─────────────┐         ┌─────────────┐
        │ Claude Code │         │    Codex    │
        └──────┬──────┘         └──────┬──────┘
               │  开局自动读 ↓   ↑ 收工自动写  │
               ▼                              ▼
        ┌──────────────────────────────────────────┐
        │  AI-cross-agent/projects/<项目>/*.md       │
        │  （PROTOCOL 协议 + 各终端历史摘要）          │
        └──────────────────────────────────────────┘
```

**闭环**：进项目 → 自动读协议+历史摘要 → 干活 → 每轮自动留总结 → 另一终端开局自动接续。

---

## 目录结构

```
AI-cross-agent/
├── README.md          ← 本文件
├── PROTOCOL.md        ← 协议正文（所有终端的行为契约，唯一维护点）
├── INDEX.md           ← 已接入项目索引（脚本自动维护）
├── install.sh         ← 一键安装：写入两个工具的全局配置
├── uninstall.sh       ← 卸载：移除注入的配置块
├── add-project.sh     ← 接入一个新项目
└── projects/          ← 各项目的摘要目录（每接入一个项目生成一个子目录）
    └── <项目名>/
        ├── project.md       ← 项目画像
        ├── claude-code.md   ← Claude Code 的历史摘要（按轮追加）
        └── codex.md         ← Codex 的历史摘要
```

> 套件可放在磁盘任意位置，脚本会自动按自身所在路径工作。

## 快速开始（3 步）

### 1. 安装（写入两个工具的全局配置，幂等可重复）

```bash
cd AI-cross-agent
./install.sh
```

它会把一段「自动加载协议」的引导**追加**到：
- `~/.claude/CLAUDE.md`（Claude Code 每次会话自动读）
- `~/.codex/AGENTS.md`（Codex 每次会话自动读）

> 用标记块包裹，不会破坏你已有的内容；重复运行只替换自己的块。

### 2. 接入你的项目

```bash
./add-project.sh /路径/到/你的项目          # 简介自动从该项目 README 提取
./add-project.sh /路径/到/你的项目 "一句话简介"  # 或手动指定简介
```

执行后会：建 `projects/<项目名>/`、写 `project.md`、在项目根放 `CLAUDE.md`+`AGENTS.md`、登记到 `INDEX.md`。

### 3. 正常使用

用 Claude Code 或 Codex **打开该项目目录**开始工作即可。它们会自动：
- 开局先读协议和历史摘要，并向你简述上次进展；
- 每轮回复结束时把本轮进展追加到对应的摘要文件——**无需你说“结束”**。

## 日常使用

| 想做的事 | 怎么做 |
|----------|--------|
| 接入新项目 | `./add-project.sh <项目路径>`，或直接对 AI 说「把 X 接入协作协议」（它会自己跑脚本）|
| 查看某项目历史 | 打开 `projects/<项目名>/` 下的 `*.md`，或 `git log <项目名>` |
| 看已接入哪些项目 | 打开 `INDEX.md` |
| 改协议规则 | 只改 `PROTOCOL.md`（唯一维护点），其余文件是指向它的薄指针 |
| 卸载 | `./uninstall.sh`（保留摘要与项目内文件） |

## Git 分支管理（一项目一分支）

本套件是一个 git 仓库，采用「一项目一分支」策略，让每个项目的摘要历史互不干扰：

- **main 分支**：维护协议文件（`PROTOCOL.md`、`INDEX.md`、`add-project.sh` 等）
- **项目分支**（分支名 = 项目名）：存放 `projects/<项目名>/` 下的摘要文件

`add-project.sh` 接入新项目时会自动创建对应分支并提交初始 `project.md`，然后切回 `main`。
每轮工作结束追加摘要后，按如下流程提交：

```bash
git checkout <项目名>
git add projects/<项目名>/<终端名>.md
git commit -m "项目 <项目名>: <本轮简短描述>"
git checkout main
```

## 工作原理（为什么「自动」生效）

1. **全局配置**：`install.sh` 在两个工具的全局文件里写入引导，使**任何**已接入项目都触发协议。
2. **项目级文件**：`add-project.sh` 在每个项目根放 `CLAUDE.md`（Claude Code 自动加载）和
   `AGENTS.md`（Codex 自动加载）。即使你只在子项目目录里打开终端也能读到协议——
   因为这份文件就在你打开的目录里，不依赖父目录上溯。
3. 这些文件都是**薄指针**，内含指向 `PROTOCOL.md` 的**绝对路径**；规则只维护在协议一处。

---

## 限制与注意

- **摘要是「行为指令」，不是硬性钩子**：模型绝大多数情况会照做，但偶尔某一轮可能漏写。
  它无法 100% 强制——因为有内容的总结只能由模型生成。
- **依赖套件目录可访问**：若套件放在外置磁盘/网络盘，使用时需保证它已挂载。
- **路径在接入时被「焊死」**：`add-project.sh` 把套件的绝对路径写进各项目文件。
  若之后移动了套件目录，请对相关项目重新运行一次 `add-project.sh`，并重跑 `install.sh`。
- 目前内置 **Claude Code** 与 **Codex**。接入其它工具：在其全局规则文件里仿照 `install.sh`
  的引导块指向本协议，并约定一个 `<终端名>.md` 即可。

---

## 卸载

```bash
./uninstall.sh
```

仅移除注入到 `~/.claude/CLAUDE.md` 和 `~/.codex/AGENTS.md` 的标记块；
`projects/` 下的历史摘要、以及各项目根的 `CLAUDE.md`/`AGENTS.md` 会保留
（如不再需要可手动删除对应项目根的这两个文件）。
